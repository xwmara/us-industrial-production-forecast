# Format a p-value for the text, including the relation sign ("= 0.0100", "< 2.2e-16")
fmt_p <- function(p) {
  if (p < 2.2e-16) return("< 2.2e-16")
  if (p < 0.001) return(paste("=", format(p, digits = 3, scientific = TRUE)))
  paste("=", sprintf("%.4f", p))
}

# KPSS statistics with the 5% critical value
kpss_table <- function(x) {
  do.call(rbind, lapply(c("tau", "mu"), function(type) {
    t <- ur.kpss(x, type = type)
    data.frame(
      Specification = if (type == "tau") "Trend (tau)" else "Constant (mu)",
      Statistic = round(t@teststat, 4),
      `Critical value 5%` = t@cval[, "5pct"],
      check.names = FALSE
    )
  }))
}

# ADF p-values for several lag orders (tseries reports p-values within [0.01, 0.99])
adf_lags <- c(1, 2, 3, 4, 5, 12, 24)
adf_table <- function(x) {
  data.frame(
    Lag = adf_lags,
    `p-value` = sapply(adf_lags, function(k) suppressWarnings(adf.test(x, k = k)$p.value)),
    check.names = FALSE
  )
}

# HEGY statistics and p-values by frequency. The test regression includes a
# constant, a linear trend and monthly dummies (deterministic = c(1, 1, 1)), and
# the number of augmentation lags is chosen by BIC so that its residuals are not
# autocorrelated.
hegy_table <- function(x) {
  h <- hegy.test(x, deterministic = c(1, 1, 1), lag.method = "BIC", maxlag = 12)
  data.frame(
    Statistic = names(h$statistics),
    Value = round(h$statistics, 3),
    `p-value` = round(h$pvalues, 4),
    check.names = FALSE,
    row.names = NULL
  )
}

The series is the US Industrial Production Total Index (IPB50001N, 2017 = 100, not seasonally adjusted), monthly from January 1990 to April 2025 (424 observations).

Visual analysis

Code 
autoplot(ip_ts) +
  labs(x = "Year", y = "Index (2017 = 100)")

The series has a strong upward trend between 1990 and 2008, so its mean is not constant, which is a first sign of non-stationarity. Two major shocks stand out: the collapse during the 2008–2009 financial crisis and the very sharp but short-lived drop during the COVID-19 pandemic in 2020. The trend and the level shifts call for formal unit root testing.

Code 
ggtsdisplay(ip_ts)

The ACF decays very slowly and almost linearly, staying far above the significance bands: the classic pattern of a non-stationary (unit root) process. The PACF has a large spike at lag 1 and significant spikes at the seasonal lags 12 and 24. Visually, the series needs both a regular difference (for the trend) and a seasonal difference at lag 12.

Code 
ggsubseriesplot(ip_ts) +
  labs(x = NULL, y = "Index (2017 = 100)")

The monthly means differ: June and August have the highest average production, while April and July are lower. Unequal monthly means are visual evidence of a seasonal component, which motivates the HEGY test for seasonal unit roots.

Stationarity tests in levels

KPSS (null hypothesis: the series is stationary):

Code 
kpss_level <- kpss_table(ip_ts)
kpss_level

In both specifications the statistic is far above the 5% critical value, so stationarity is rejected: the original series is non-stationary.

ADF (null hypothesis: unit root) for several lag orders, and Phillips-Perron:

Code 
adf_level <- adf_table(ip_ts)
pp_level <- PP.test(ip_ts)
adf_level

All ADF p-values are well above 0.05, so the unit root cannot be rejected. The Phillips-Perron test gives p = 0.5592 and leads to the same conclusion. KPSS, ADF and PP all agree that the series is non-stationary in levels.

Seasonality test (HEGY)

Code 
hegy_level <- hegy_table(log(ip_ts))
hegy_level

The HEGY test checks for unit roots at the zero frequency (t_1, an ordinary stochastic trend) and at each seasonal frequency (t_2 and the F-statistics). Because the series has a trend and a seasonal pattern, the test regression includes a constant, a trend and monthly dummies.

  • For t_1, p = 0.4269 (> 0.05): the zero-frequency unit root is not rejected, so the series needs a regular (first) difference.
  • At all seasonal frequencies the p-values are below 0.01: seasonal unit roots are rejected. The seasonal pattern is deterministic (a stable pattern by month), not stochastic.

Strictly, this points to a first difference with monthly dummies rather than a seasonal difference. The analysis below follows the usual SARIMA route with both a log transformation and a seasonal difference at lag 12, which is also what auto.arima() selects. Seasonally differencing a series without seasonal unit roots can over-difference it; this would show up as a seasonal MA coefficient close to −1 in the SARIMA model, which is checked below.

The KPSS statistics are now far below their 5% critical values, so stationarity is not rejected. The first 75% of the sample (318 months, to Jun 2016) is used to estimate the models; the last 106 months (Jul 2016 to Apr 2025) are kept for out-of-sample evaluation. The forecast horizon h equals the length of the test set, so RMSE, MAE and MAPE can be computed on it.

ARMA models on the stationary series

Short lags (1–4) are significant in both the ACF and PACF, which points to short-run AR and MA components. There are also large negative spikes at the seasonal lags 12 and 24, so a non-seasonal ARMA model will struggle to remove the autocorrelation at long lags. This is why several models are estimated and why SARIMA follows.

  1. Autocorrelation (Ljung-Box): all p-values are high (minimum 0.882), so the residuals are independent and the dynamics have been captured.
  2. Normality (Jarque-Bera): p < 2.2e-16 (< 0.05), so normality is rejected. This is explained by turning points and major shocks (the 2008 crisis and the 2020 COVID-19 shock).
  3. Heteroscedasticity (ARCH): p-values below 0.05 show ARCH effects (volatility clustering): the error variance is not constant, with larger residuals during episodes of macroeconomic instability.

The model is valid for the conditional mean and is used for forecasting.

SARIMA forecast

Code 
# Back-transform to index levels. The same model (same coefficients) is applied
# to the series with lambda = 0, i.e. a log transformation, so forecast()
# returns exp() of the log forecasts: the point forecast is the median of the
# forecast distribution and the interval bounds (quantiles) carry over exactly.
sarima_lvl <- Arima(ip_train, model = sarima_final, lambda = 0)
sarima_real <- forecast(sarima_lvl, h = h)

# For comparison: the bias-adjusted mean forecast
sarima_mean <- forecast(Arima(ip_train, model = sarima_final, lambda = 0, biasadj = TRUE), h = h)
sarima_mean_rmse <- accuracy(sarima_mean$mean, ip_test)[1, "RMSE"]

autoplot(sarima_real) +
  autolayer(ip_test, series = "Test data") +
  labs(title = NULL, x = "Year", y = "Index (2017 = 100)", colour = NULL)
  1. The forecasts are made for the log of the index and converted back with exp(). This gives the median forecast, and the prediction intervals stay valid because quantiles are preserved by exp(). The mean forecast would be higher by roughly half the forecast variance, which grows quickly with the horizon: the gap is 0.1 index points after 12 months but 8.3 after 106 months, and the RMSE on the test period would be 4.63 instead of 2.93. The median is used as the point forecast.
  2. The forecast (blue) follows the centre of the test data (2016–2025) closely from this single origin; the rolling-origin evaluation below gives a more complete picture of out-of-sample performance.
  3. The 2020 COVID-19 shock appears as a large exogenous deviation; the data later return to the forecast path.
  4. The uncertainty fan widens asymmetrically, as expected for long-horizon forecasts on a log scale.

The chart is consistent with the accuracy table. SARIMA follows the level and the fluctuations of the actual series closely, around 100 index points. ETS and Holt-Winters drift downwards and underestimate the series, which explains their large errors. The seasonal naive forecast does reasonably well thanks to its flat trend but does not adapt to the dynamics of the series.

This comparison rests on a single forecast origin (June 2016): each error is a forecast from 1 to 106 months ahead, and the result depends heavily on where the trend of each model happened to point in mid-2016. The errors are also strongly autocorrelated (first-order autocorrelation of 0.82 for SARIMA), so a Diebold-Mariano test that treats them as independent one-step errors would overstate the significance of the differences. A rolling-origin evaluation gives a more reliable comparison.

Rolling-origin evaluation

Here the models are re-estimated every month of the test period on all data available up to that month (an expanding window) and forecast the next 1 to 12 months, as an analyst updating the forecast every month would do. Each model keeps the specification selected on the training data; only its parameters are re-estimated. SARIMA forecasts are medians, as above.

Code 
max_h <- 12
sarima_order <- arimaorder(sarima_final)

# Forecast functions with the specifications chosen on the training data
ets_spec <- ets_auto$components  # error, trend, season, damped
forecast_functions <- list(
  SARIMA = function(x, h) {
    forecast(Arima(x, order = sarima_order[c("p", "d", "q")],
                   seasonal = sarima_order[c("P", "D", "Q")], lambda = 0), h = h)
  },
  ETS = function(x, h) {
    forecast(ets(x, model = paste0(ets_spec[1], ets_spec[2], ets_spec[3]),
                 damped = as.logical(ets_spec[4])), h = h)
  },
  `Holt-Winters` = function(x, h) hw(x, seasonal = "additive", h = h),
  `Seasonal naive` = function(x, h) snaive(x, h = h)
)

# Row t, column k = error of the k-step forecast made with data up to month t.
# The first origin is the end of the training sample (June 2016).
cv_errors <- lapply(forecast_functions, function(f) {
  tsCV(ip_ts, f, h = max_h, initial = n_train - 1)
})

# Actual value and target date of each k-step forecast, aligned with cv_errors
n_obs <- length(ip_ts)
target_value <- function(k) c(as.numeric(ip_ts)[-(1:k)], rep(NA, k))
target_time <- function(k) c(as.numeric(time(ip_ts))[-(1:k)], rep(NA, k))

cv_accuracy <- function(k, exclude_covid = FALSE) {
  keep <- !is.na(target_value(k))
  if (exclude_covid) {
    keep <- keep & !(target_time(k) >= 2020 + 2 / 12 & target_time(k) < 2021.5)
  }
  t(sapply(cv_errors, function(E) {
    e <- E[, k]
    ok <- keep & !is.na(e)
    c(Forecasts = sum(ok),
      RMSE = sqrt(mean(e[ok]^2)),
      MAE = mean(abs(e[ok])),
      `MAPE (%)` = 100 * mean(abs(e[ok] / target_value(k)[ok])))
  }))
}

cv_1 <- cv_accuracy(1)
cv_12 <- cv_accuracy(12)

Diebold-Mariano tests

The Diebold-Mariano test compares the squared errors of SARIMA with those of each other model on the same forecast origins. The null hypothesis is equal accuracy; a negative statistic means SARIMA has smaller errors. For 12-month forecasts, consecutive errors overlap, and h = 12 makes the test account for the resulting autocorrelation.

# Format a p-value for the text, including the relation sign ("= 0.0100", "< 2.2e-16")
fmt_p <- function(p) {
  if (p < 2.2e-16) return("< 2.2e-16")
  if (p < 0.001) return(paste("=", format(p, digits = 3, scientific = TRUE)))
  paste("=", sprintf("%.4f", p))

# KPSS statistics with the 5% critical value
kpss_table <- function(x) {
  do.call(rbind, lapply(c("tau", "mu"), function(type) {
    t <- ur.kpss(x, type = type)
    data.frame(
      Specification = if (type == "tau") "Trend (tau)" else "Constant (mu)",
      Statistic = round(t@teststat, 4),
      `Critical value 5%` = t@cval[, "5pct"],
      check.names = FALSE
    )
  }))
}

# ADF p-values for several lag orders (tseries reports p-values within [0.01, 0.99])
adf_lags <- c(1, 2, 3, 4, 5, 12, 24)
adf_table <- function(x) {
  data.frame(
    Lag = adf_lags,
    `p-value` = sapply(adf_lags, function(k) suppressWarnings(adf.test(x, k = k)$p.value)),
    check.names = FALSE
  )
}

# HEGY statistics and p-values by frequency. The test regression includes a
# constant, a linear trend and monthly dummies (deterministic = c(1, 1, 1)), and
# the number of augmentation lags is chosen by BIC so that its residuals are not
# autocorrelated.
hegy_table <- function(x) {
  h <- hegy.test(x, deterministic = c(1, 1, 1), lag.method = "BIC", maxlag = 12)
  data.frame(
    Statistic = names(h$statistics),
    Value = round(h$statistics, 3),
    `p-value` = round(h$pvalues, 4),
    check.names = FALSE,
    row.names = NULL
  )
}

## Seasonality test (HEGY)

```{r}
#| label: tbl-hegy-level
#| tbl-cap: "HEGY test on the log series (constant, trend and monthly dummies; lags chosen by BIC)"
hegy_level <- hegy_table(log(ip_ts))
hegy_level
```

The HEGY test checks for unit roots at the zero frequency (`t_1`, an ordinary
stochastic trend) and at each seasonal frequency (`t_2` and the F-statistics).
Because the series has a trend and a seasonal pattern, the test regression
includes a constant, a trend and monthly dummies.

- For `t_1`, p
  `r fmt_p(hegy_level[["p-value"]][hegy_level$Statistic == "t_1"])` (> 0.05):
  the zero-frequency unit root is not rejected, so the series needs a regular
  (first) difference.
- At all seasonal frequencies the p-values are below
  `r ceiling(100 * max(hegy_level[["p-value"]][hegy_level$Statistic != "t_1"])) / 100`:
  seasonal unit roots are rejected. The seasonal pattern is **deterministic**
  (a stable pattern by month), not stochastic.

Strictly, this points to a first difference with monthly dummies rather than a
seasonal difference. The analysis below follows the usual SARIMA route with
both a log transformation and a seasonal difference at lag 12, which is also
what `auto.arima()` selects. Seasonally differencing a series without seasonal
unit roots can over-difference it; this would show up as a seasonal MA
coefficient close to −1 in the SARIMA model, which is checked below.

   (MAPE = `r round(acc_table["SNAIVE", "MAPE"], 2)`%).

The chart is consistent with the accuracy table. SARIMA follows the level and
the fluctuations of the actual series closely, around 100 index points. ETS and
Holt-Winters drift downwards and underestimate the series, which explains their
large errors. The seasonal naive forecast does reasonably well thanks to its
flat trend but does not adapt to the dynamics of the series.

This comparison rests on a **single forecast origin** (June 2016): each error
is a forecast from 1 to `r h` months ahead, and the result depends heavily on
where the trend of each model happened to point in mid-2016. The errors are
also strongly autocorrelated (first-order autocorrelation of
`r round(acc_table["SARIMA", "ACF1"], 2)` for SARIMA), so a Diebold-Mariano test
that treats them as independent one-step errors would overstate the
significance of the differences. A rolling-origin evaluation gives a more
reliable comparison.

## Rolling-origin evaluation

Here the models are re-estimated every month of the test period on all data
available up to that month (an expanding window) and forecast the next 1 to 12
months, as an analyst updating the forecast every month would do. Each model
keeps the specification selected on the training data; only its parameters are
re-estimated. SARIMA forecasts are medians, as above.

```{r}
#| label: rolling-cv
max_h <- 12
sarima_order <- arimaorder(sarima_final)

# Forecast functions with the specifications chosen on the training data
ets_spec <- ets_auto$components  # error, trend, season, damped
forecast_functions <- list(
  SARIMA = function(x, h) {
    forecast(Arima(x, order = sarima_order[c("p", "d", "q")],
                   seasonal = sarima_order[c("P", "D", "Q")], lambda = 0), h = h)
  },
  ETS = function(x, h) {
    forecast(ets(x, model = paste0(ets_spec[1], ets_spec[2], ets_spec[3]),
                 damped = as.logical(ets_spec[4])), h = h)
  },
  `Holt-Winters` = function(x, h) hw(x, seasonal = "additive", h = h),
  `Seasonal naive` = function(x, h) snaive(x, h = h)
)

# Row t, column k = error of the k-step forecast made with data up to month t.
# The first origin is the end of the training sample (June 2016).
cv_errors <- lapply(forecast_functions, function(f) {
  tsCV(ip_ts, f, h = max_h, initial = n_train - 1)
})

# Actual value and target date of each k-step forecast, aligned with cv_errors
n_obs <- length(ip_ts)
target_value <- function(k) c(as.numeric(ip_ts)[-(1:k)], rep(NA, k))
target_time <- function(k) c(as.numeric(time(ip_ts))[-(1:k)], rep(NA, k))

cv_accuracy <- function(k, exclude_covid = FALSE) {
  keep <- !is.na(target_value(k))
  if (exclude_covid) {
    keep <- keep & !(target_time(k) >= 2020 + 2 / 12 & target_time(k) < 2021.5)
  }
  t(sapply(cv_errors, function(E) {
    e <- E[, k]
    ok <- keep & !is.na(e)
    c(Forecasts = sum(ok),
      RMSE = sqrt(mean(e[ok]^2)),
      MAE = mean(abs(e[ok])),
      `MAPE (%)` = 100 * mean(abs(e[ok] / target_value(k)[ok])))
  }))
}

cv_1 <- cv_accuracy(1)
cv_12 <- cv_accuracy(12)
```

### Diebold-Mariano tests

The Diebold-Mariano test compares the squared errors of SARIMA with those of
each other model on the same forecast origins. The null hypothesis is equal
accuracy; a negative statistic means SARIMA has smaller errors. For 12-month
forecasts, consecutive errors overlap, and `h = 12` makes the test account for
the resulting autocorrelation.

```{r}
#| label: tbl-dm
#| tbl-cap: "Diebold-Mariano tests on rolling-origin errors (SARIMA vs each model)"
dm_rows <- list()
for (k in c(1, max_h)) {
  for (m in setdiff(names(cv_errors), "SARIMA")) {
    a <- cv_errors$SARIMA[, k]
    b <- cv_errors[[m]][, k]
    ok <- !is.na(a) & !is.na(b)
    test <- dm.test(a[ok], b[ok], alternative = "two.sided", h = k, power = 2)
    dm_rows[[length(dm_rows) + 1]] <- data.frame(
      Horizon = paste(k, if (k == 1) "month" else "months"),
      Comparison = paste("SARIMA vs", m),
      `DM statistic` = round(unname(test$statistic), 3),
      `p-value` = signif(test$p.value, 3),
      check.names = FALSE
    )
  }
}
dm_table <- do.call(rbind, dm_rows)
rownames(dm_table) <- NULL

# Display copy with readable p-values
dm_display <- dm_table
dm_display[["p-value"]] <- ifelse(
  dm_table[["p-value"]] < 0.001,
  format(dm_table[["p-value"]], digits = 3, scientific = TRUE),
  sprintf("%.3f", dm_table[["p-value"]])
)
dm_display
```

```{r}
#| label: dm-values
dm_p <- function(horizon, model) {
  dm_table[["p-value"]][dm_table$Horizon == horizon & dm_table$Comparison == paste("SARIMA vs", model)]
}
```

1. **One month ahead**, SARIMA, ETS and Holt-Winters are very close (RMSE of
   `r sprintf("%.2f", cv_1["SARIMA", "RMSE"])` for SARIMA,
   `r sprintf("%.2f", cv_1["ETS", "RMSE"])` for ETS and
   `r sprintf("%.2f", cv_1["Holt-Winters", "RMSE"])` for Holt-Winters), and the
   Diebold-Mariano test does not distinguish SARIMA from ETS (p `r fmt_p(dm_p("1 month", "ETS"))`) or
   Holt-Winters (p `r fmt_p(dm_p("1 month", "Holt-Winters"))`). All three clearly
   beat the seasonal naive benchmark (RMSE
   `r round(cv_1["Seasonal naive", "RMSE"], 2)`; SARIMA vs seasonal naive
   p `r fmt_p(dm_p("1 month", "Seasonal naive"))`).
2. **Twelve months ahead**, the seasonal naive forecast has the lowest errors
   (RMSE `r round(cv_12["Seasonal naive", "RMSE"], 2)` against
   `r round(cv_12["SARIMA", "RMSE"], 2)` for SARIMA), but none of the
   differences is statistically significant (all p-values above
   `r floor(100 * min(dm_table[["p-value"]][dm_table$Horizon == "12 months"])) / 100`).
3. Excluding the pandemic months lowers all errors substantially. One month
   ahead the three statistical models remain almost tied, and twelve months
   ahead the seasonal naive forecast is still the most accurate.

The rolling-origin evaluation does **not** confirm the large advantage of
SARIMA seen with a single forecast origin. At short horizons (one to a few
months) the three statistical models perform equally well and all beat the
seasonal naive benchmark; at a one-year horizon no model beats simply repeating
the last year's values.

## Forecast beyond the sample

The test period is only used to evaluate the models. To forecast the future,
the selected SARIMA specification is re-estimated on the full sample
(January 1990 to April 2025), so the forecast uses all the available data,
including the years after 2016.

Re-estimating on the full sample keeps the same model structure
(`r as.character(sarima_full)`) but updates the coefficients with the data up
to April 2025. The point forecast stays close to the recent level of the index,
around `r round(mean(future$mean[1:12]), 0)` index points over the next 12
months, while the 95% interval widens from
±`r round((future$upper[1, "95%"] - future$lower[1, "95%"]) / 2, 1)` points one
month ahead to about
±`r round((future$upper[h_future, "95%"] - future$lower[h_future, "95%"]) / 2, 0)`
points after three years.
